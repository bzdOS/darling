# Instrumented lld harness: OPTION-table format skew

## What the harness is

An out-of-tree `ld64.lld` built from the system lld Mach-O sources plus one
hand-maintained `main()` that prints markers around the call:

```
main: start
main: handler initialized
main: calling link
...
main: link returned <n>
```

It is used to reproduce a crash in `lld::macho::link` without a full toolchain
build. `main()` returns the `bool` that `lld::macho::link()` returns, so its
exit code is **inverted** relative to the real `ld.lld` (`true` → 1). Read the
stderr text and the reference binary, not the harness exit code alone.

## The defect

`ld64.lld -v` died with SIGSEGV (rc=139) inside the option-table constructor:

```
frame #0  llvm::opt::GenericOptTable::GenericOptTable(StringTable const&,
             ArrayRef<StringTable::Offset>, ArrayRef<OptTable::Info>, bool) + 384
frame #1  lld::macho::MachOOptTable::MachOOptTable() + 121
frame #2  lld::macho::link(ArrayRef<const char*>, raw_ostream&, raw_ostream&,
             bool, bool) + 294
frame #3  main + 344
```

The cause is a **skew between two generations of the option table format**:

* `lld/MachO/DriverUtils.cpp` is pre-`StringTable`: it pulls prefix literals out
  of the generated file with a `PREFIX(NAME, VALUE)` macro and calls the
  one-argument `GenericOptTable(optInfo)`.
* `Options.inc` regenerated by a current `llvm-tblgen` emits
  `llvm::StringTable OptionStrTable`, `OptionPrefixesTable`, and a **two**
  argument constructor `GenericOptTable(StrTable, PrefixesTable, InfoArray)`.

So an option with prefixes (`-arch`, `--help`, …) carries a non-zero
`PrefixesOffset`, while the harness passed an **empty** `PrefixesTable`. The
constructor then indexes `PrefixesTable[PrefixesOffset]` out of bounds and
segfaults before any option is ever parsed.

`Info` itself is not skewed — both generations agree on the 14 `OPTION(...)`
arguments and the record layout (measured: `sizeof(OptTable::Info)` == 80,
374 entries, 29920 bytes of `optInfo`).

## The fix

Use the tables the generator itself emits (`patches/DriverUtils.opt-table.patch`,
6 lines):

```c++
#define OPTTABLE_STR_TABLE_CODE
#include "Options.inc"
#undef OPTTABLE_STR_TABLE_CODE

#define OPTTABLE_PREFIXES_TABLE_CODE
#include "Options.inc"
#undef OPTTABLE_PREFIXES_TABLE_CODE

MachOOptTable::MachOOptTable()
    : GenericOptTable(OptionStrTable, OptionPrefixesTable, optInfo) {}
```

No hand-written table: `OptionStrTable` and `OptionPrefixesTable` are the
generator's output, so the record array and the prefix array cannot drift apart
again.

## Reproduction

```sh
sh build-freebsd/lld-harness/gen-options.sh          # tblgen step, byte-identical table
sh build-freebsd/lld-harness/build-ld64.sh            # compile DriverUtils, link, run the check
```

Expected, measured on a host with llvm21 under `/usr/local`:

| command | before the patch | after the patch |
| --- | --- | --- |
| `ld64.lld -v` | rc=139, SIGSEGV in `GenericOptTable` | rc=0, `error: must specify -arch` |
| `ld64.lld --help` | rc=139, SIGSEGV | 259 lines of option help |
| `ld64.lld -arch x86_64 -v` | rc=139, SIGSEGV | same two errors as `ld.lld -flavor darwin` |

The reference binary `ld.lld -flavor darwin -v` prints `error: must specify
-arch` too: `config()` runs before the `-v` handler (`Driver.cpp:800` vs
`Driver.cpp:1518`). Our harness prints the same stderr text; its exit code is
inverted by the harness `main()` described above.

`--help` output (259 lines) is a subset of the reference output (297 lines):
the system `lld/MachO/Options.td` is older and lacks options added upstream
later (`--bp-compression-sort`, `--icf=safe_thunks`, …). That difference is the
table's content, not its format.

## Files

* `gen-options.sh` — the exact `llvm-tblgen --gen-opt-parser-defs` invocation.
* `generated/Options.inc` — its output (sha256 `8fa50f25…72c294`, 126533 bytes);
  regenerate and compare rather than edit.
* `patches/DriverUtils.opt-table.patch` — the patch against the tree's
  `lld/MachO/DriverUtils.cpp`.
* `build-ld64.sh` — compile the patched file, link the harness, run the check.
